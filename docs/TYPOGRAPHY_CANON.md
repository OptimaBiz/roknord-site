# Канон типографики ROKNORD

Этот документ обязателен для всех существующих и новых страниц, блоков и компонентов. Система следует принципам человекоцентричного проектирования ISO 9241-210 и доступности WCAG; она не является заявлением о сертификации сайта по ISO.

## Шрифтовые роли

- `Onest` — весь интерфейс, основной текст и заголовки.
- `JetBrains Mono` — цены, номера, стандарты, реквизиты и другие технические данные.
- Не подключать новые гарнитуры без изменения канона.
- Использовать веса 400, 500, 600 и 700. Не применять синтетические или промежуточные веса.

## Семантическая шкала

Размер задаётся только токеном роли из `src/styles/tokens.css`:

- `--type-page-title` — главный заголовок внутренней страницы.
- `--type-display` — крупный композиционный заголовок.
- `--type-section-title` — заголовок секции.
- `--type-feature-title` — крупный заголовок смыслового блока.
- `--type-card-title` — заголовок карточки, модального окна или формы.
- `--type-subsection-title` — заголовок вложенного блока.
- `--type-lead` — лид и вводный абзац.
- `--type-body` — основной текст.
- `--type-control` — кнопки и элементы управления.
- `--type-label` — подписи полей и навигационные метки.
- `--type-caption` — служебная информация и надписи верхнего регистра.
- `--type-data-display` и `--type-step-number` — крупные данные и номера этапов.

## Правила применения

1. Не задавать произвольный `font-size` внутри компонента, если роль уже существует.
2. Новый размер сначала оформляется как семантический токен и только затем используется в компоненте.
3. Один смысловой уровень имеет одинаковый размер, вес и интерлиньяж на всех маршрутах.
4. Заголовки используют `text-wrap: balance`, не разрываются внутри слова и не выходят за ширину экрана.
5. Основной текст имеет интерлиньяж не меньше 1.5; длинные строки ограничиваются читаемой шириной.
6. Интерактивный текст на мобильных устройствах остаётся читаемым, а поля ввода имеют размер не меньше 16 px для предотвращения автоматического масштабирования.
7. Верхний регистр допустим только для коротких меток; он всегда сопровождается умеренным межбуквенным интервалом.
8. Цвет, размер и вес не должны быть единственным способом передать состояние элемента.
9. Адаптивность строится через общие fluid-токены, а не через отдельные несогласованные размеры на каждой странице.
10. Исключения допустимы только для hero-композиции, цены и номера этапа и должны использовать именованный токен.

## Проверка новой страницы

- На ширинах 320, 390, 768 и 1440 px нет горизонтального переполнения.
- Заголовки не обрезаются и не распадаются по буквам.
- Визуальная иерархия читается без цвета: страница → секция → карточка → основной текст → подпись.
- Все элементы управления используют общие типографические и motion-токены.
- Технические данные используют моноширинную роль, обычный текст — `Onest`.
- Проверены фокус, клавиатурная навигация и `prefers-reduced-motion`.

# Клиентский кабинет Рокнорд

Клиентский интерфейс: `/account/`, Astro + обычный TypeScript. Сервер: PHP 8.3+, PDO SQLite, mbstring, fileinfo, sessions. Один текущий проект на аккаунт. Данные не встроены в HTML и не сохраняются в localStorage.

В кабинете доступны договоры и приложения, рабочие документы и результаты, передача PDF до 10 МБ (100 МБ на аккаунт), задачи, последние 100 сообщений, текущий этап, следующий шаг, координатор и смена пароля. Размещение документа не означает его подписание. Отметка задачи не является приёмкой результата. Электронная подпись, платежи и email-уведомления не реализованы.

## Локальный запуск

Из корня репозитория:

```sh
npm ci
npm run build
docker compose -f docker-compose.portal.yml run --rm seed
docker compose -f docker-compose.portal.yml up -d portal
```

Открыть `http://127.0.0.1:4387/account/`.

- Почта: `demo@roknord.example`
- Пароль: `Roknord-Demo-2026!`

Это вымышленный клиент. Три TXT-файла явно обозначены как учебные образцы, а не подписанный договор или клиентский отчёт. Демо создаётся только по отдельной CLI-команде; повторный запуск не перезаписывает данные. Вход демо запрещён вне локального PHP development server. Для работы с настоящими клиентами создайте индивидуальные аккаунты.

Данные сохраняются в Docker volume `portal-data`. Остановка без удаления данных:

```sh
docker compose -f docker-compose.portal.yml down
```

`npm run dev` и `npm run preview` показывают только статический интерфейс; для работающего входа используйте PHP-просмотр выше. Сервер привязан к loopback, не к публичному интерфейсу.

## Размещение на Timeweb

`npm run deploy:timeweb` устанавливает PHP-кабинет по SSH перед загрузкой статического `dist/`. Команда проверяет PHP 8.3+ и расширения, размещает код вне `public_html`, запускает идемпотентную инициализацию схемы через `install.php`, затем публикует точку входа и проверяет анонимную HTTPS-сессию API. Только после успешной проверки загружается сайт; API проверяется повторно. Ошибка на любом этапе завершает команду ненулевым кодом.

Если CLI использует старый PHP, задайте путь `TIMEWEB_PHP_BIN` к PHP 8.3+ на хостинге. Версию PHP самого веб-сайта также нужно настроить в Timeweb: настройка CLI не меняет веб-обработчик. Для другого домена используется `TIMEWEB_PUBLIC_ORIGIN` (по умолчанию `https://roknord.ru`). Доступ должен иметь пользователь, от которого работает PHP.

Установка не создаёт пользователей и не загружает демо, SQLite или документы с локального компьютера. Существующие записи и файлы сохраняются. FTP для полной публикации не поддерживается: он не запускает установщик и не проверяет серверное окружение. Подробнее: `.github/TIMEWEB_DEPLOYMENT.md`.

Структура на сервере:

```text
roknord/
  public_html/
    account/index.html          # из dist
    portal-api/portal.php       # копия timeweb-entry.php
  client-portal/                # содержимое server/client-portal
    bootstrap.php
    manage.php
    public/portal.php
  client-portal-private/        # создаётся PHP; вне document root
    portal.sqlite
    files/
```

Не копируйте `bootstrap.php`, `manage.php`, базу или документы в `public_html`. Production использует HTTPS и origin `https://roknord.ru`. При другом домене задайте `ROKNORD_PORTAL_ORIGIN` серверной переменной. `ROKNORD_PORTAL_DATA` при необходимости задаёт абсолютный путь вне document root. Reverse proxy должен корректно передавать HTTPS в PHP; приложение намеренно не доверяет произвольным клиентским forwarded-заголовкам.

Настройте PHP: `upload_max_filesize=10M`, `post_max_size=12M`, `display_errors=Off`. Закройте чтение приватного каталога другим пользователям ОС, предоставив запись пользователю PHP. Настройте резервное копирование SQLite и files согласованным снимком; восстановление проверяйте отдельно. Период хранения договоров, переписки, загруженных данных и журнала действий определяется оператором. Перед реальной эксплуатацией согласуйте актуальность политики обработки данных для кабинета и работу координатора с обращениями. Текущие юридические страницы и SMTP-форма этой задачей не изменялись.

## Работа координатора

Панель администратора в браузере не входит в эту версию; обслуживание выполняется через SSH/CLI. Приложение не выдаёт клиентам административные полномочия.

Создание клиента (пароль вводится скрыто и не передаётся аргументом команды):

```sh
read -r -s -p 'Первоначальный пароль: ' ROKNORD_INITIAL_PASSWORD
export ROKNORD_INITIAL_PASSWORD
php manage.php create client@example.org 'Имя клиента' 'Организация'
unset ROKNORD_INITIAL_PASSWORD
```

Пароль: не менее 12 символов и не более 72 байт. Передайте его клиенту по согласованному приватному каналу. Для сброса используйте ту же переменную и `php manage.php reset-password client@example.org`: остальные сеансы будут отозваны.

Описание проекта находится в приватном JSON, например:

```json
{"title":"Аудит готовности","stage":"Сбор материалов","next_step":"Согласовать выборку записей","manager":"Назначенный координатор","due":"По согласованному графику"}
```

```sh
php manage.php project client@example.org /private/project.json
php manage.php document client@example.org /private/contract.pdf 'Договор №… · согласованная версия' 'Договор'
php manage.php document client@example.org /private/report.pdf 'Отчёт · версия 1' 'Результаты аудита'
php manage.php task client@example.org 'Передать область аккредитации' 'Согласованный срок'
php manage.php messages client@example.org
php manage.php documents client@example.org
php manage.php export client@example.org DOCUMENT_ID /private/new-copy.pdf
php manage.php reply client@example.org 'Материалы получены. Уточните версию документа.'
```

Команда document копирует PDF или TXT в приватное хранилище и привязывает к клиенту. Для следующей версии добавляйте документ с понятным названием. Идентификаторы случайные; загрузка через HTTP всегда проверяет принадлежность аккаунту. Вложения клиента появляются в категории «Материалы клиента»; команда documents показывает их идентификаторы, а export сохраняет копию в новый приватный файл без перезаписи существующего. Команды показывают сообщения только явно указанного клиента. Уведомления по email автоматически не отправляются.

## Проверки

```sh
node tests/portal.test.mjs
```

Тест требует запущенный локальный compose и создаёт отдельные вымышленные аккаунты. Проверяет CSRF, origin, вход, отсутствие доступа к чужим документам и задачам, загрузку PDF, переписку, смену пароля, отзыв сессий, выход и ограничения попыток. Тестовые данные остаются только в локальном volume.

`tests/browser-review.mjs` проверяет страницы в Chromium на 1440/768/390/320 px, меню, якоря, reduced motion и вход. Путь к Chromium задаётся `CHROMIUM_PATH`. Переменная `REVIEW_OUTPUT` включает снимки во временный каталог. Внешние запросы, включая отправку контактной формы и аналитику, заблокированы тестом.

Сессия: 30 минут бездействия, максимум 8 часов, HttpOnly + SameSite=Strict, Secure в production. Пароли хешируются PHP `password_hash`; при смене пароля увеличивается версия учётных данных. Все записи требуют CSRF и проверенный origin. Ответы API и документы имеют `Cache-Control: no-store`, скачивания — attachment. Имена и сообщения выводятся через textContent.
